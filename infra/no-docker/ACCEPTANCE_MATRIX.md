## Inventory parity pha 0: action Flutter ↔ REST/STOMP ↔ case

Bảng dưới là **bản đối chiếu tĩnh từ repository Flutter, `DioClient`/provider STOMP và controller liên quan**, chưa phải kết quả chạy hoặc xác nhận tất cả màn hình đã gọi các action. `:id`, `:targetId` và các tên tương tự là tham số route. Các action ngăn bởi `;` là **subcase riêng** dưới case ID ở cột cuối, không được chấm PASS cả dòng. Với từng action phải bổ sung actor/role, request input, status/body/frame, side effect SQL/Mongo/Valkey/media, event hoặc absence, và evidence như quy tắc đầu tài liệu. Giá trị runtime và các action chỉ có trong page/provider/controller nhưng chưa có ở repository vẫn `PENDING` cho đến khi rà hết `frontend/lib` và controller; **không được đóng pha 0 bằng riêng bảng tĩnh này**. Màn hình React phải có hành vi tương ứng và negative case bảo mật sau khi backend được sửa trong đợt riêng.

## CI và vận hành bắt buộc

1. CI hosted runner cài PostgreSQL native, đặt `RUN_NATIVE_POSTGRES_TESTS=true` để chạy repository integration cùng Maven unit tests, rồi build bundle trên Windows sau khi job test đạt. Testcontainers đã được gỡ khỏi group-service; workflow chưa chạy lại nên trạng thái **PENDING**, chưa tuyên bố CI pass. Không dùng `services:` container, Docker action hoặc Supabase CLI lệnh phụ thuộc Docker. Cloud conformance chạy riêng từ trusted `main` với credential test, không từ PR.
2. Đo artifact/retention GitHub Actions và quota OCI; artifact gắn SHA/provenance, từ chối sai repo/workflow/branch/checksum. Hai push liên tiếp không đảo deploy; smoke fail chỉ auto rollback code nếu schema/data/event tương thích; Pages chỉ publish sau backend gate và giữ bản cũ nếu lỗi.
3. Trên A1 ARM64 thật, chạy đủ 19 JAR, Kafka, Valkey, Caddy, Alloy, deploy agent. Hai người dùng làm workload 60 phút (upload/video, feed, chat, search, moderation), ghi p95 và RSS/PSS/heap/CPU/`MemAvailable`/swap/lag/disk/pool wait. Không OOM/restart/swap thrash; so ngưỡng **đề xuất** trong PLAN, không lấy bundle ≤10 GB làm số đo VM.
4. Ba reboot/cold start, restart Kafka/Valkey/consumer, full-disk alert, provider pause/failure/resume; không nhân đôi PID/format lại Kafka. Diễn tập backup/restore SQL/Mongo/media/offset vào môi trường cách ly và so checksum. RPO/RTO chỉ là mục tiêu cho đến khi đo.
5. Tắt laptop ít nhất 7 ngày, monitor **ngoài VM**, theo dõi pause/quota/chi phí, downtime và một lần Let’s Encrypt **production IP certificate renewal thật**; test staging/dry-run riêng. Không gọi kết quả là SLA.
6. Mỗi subcase có kết quả cụ thể `PASS/FAIL/BLOCKED` với evidence/commit/env; inventory pha 0 không còn action thiếu. Không chuyển runtime mặc định, retire Flutter hay công bố website nếu một blocker privacy/security, dữ liệu hoặc $0 còn mở.
